Why open source

Scrutiny is a feature.

Verify

Results you can check

A claim backed by runnable code can be tested rather than trusted. That is a higher bar, and the right one.

Reuse

Infrastructure you can build on

Data tooling, backtesting components, and research utilities are more valuable shared than rebuilt in isolation.

Improve

Errors found sooner

More readers means more chances to catch mistakes in data handling, methodology, or implementation.

Learn

Knowledge that compounds

Well-documented, reproducible work lowers the barrier to serious quantitative research for everyone.

Contributing

How to engage with the work.

Contribution guidelines and licences are defined per repository. [PLACEHOLDER — default licence, e.g. MIT or Apache-2.0]

  1. 01

    Reproduce

    Run the code and check that you get the same results. Reproduction reports are among the most useful contributions.

  2. 02

    Open an issue

    Report bugs, questionable assumptions, or methodological concerns, with enough detail to investigate.

  3. 03

    Discuss

    Propose extensions or alternative methods before writing large changes, so effort is well directed.

  4. 04

    Submit a pull request

    Follow the repository's contributing guide. [Link to CONTRIBUTING.md]
